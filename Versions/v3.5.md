# 🛠️ UI Design Engineering v3.5 — Changelog

## The Evolution

v3.5 is not a rewrite. It is a **latitude correction** of v3.

v3 fixed v3-beta's self-contradictions and shipped a solid, uniformly strict
rulebook. But uniform strictness has its own failure mode: every rule carried
the same weight, so an experimental or artistic brief was fighting the same
"BLOCKING LAWS" as a banking dashboard. Meanwhile a few rules were stated but
never actually operationalized — "calculate contrast" with no formula, "no
placeholders" with no definition of what a *legitimate* empty state is.
v3.5 fixes both problems without touching the underlying philosophy.

The fundamental rule change:
> **v3:** "Every rule applies equally, regardless of context." **v3.5:** "Some rules are load-bearing, some are defaults — say which one you're breaking, and why."

---

# ⚖️ Tiering the Rules: Non-Negotiable vs. Adaptable

## Before (v3)
- Section 1 titled **"BLOCKING LAWS (Highest Priority — Non-Negotiable)"**
- Single tier: anti-generic patterns, reference adaptation, content rules, and production mindset were all enforced with the same absolute weight
- No mechanism to deliberately break a visual convention (glassmorphism, gradient hero, tight palette) even when the brief called for it — the only escape was ignoring the skill's own rule

## Now (v3.5)
- Section 1 retitled **"Guardrails — Non-Negotiable Core vs. Adaptable Defaults"**
- Two explicit tiers:

| Tier | Covers | Can be deviated from? |
|------|--------|------------------------|
| **A — Non-negotiable** | Accessibility, semantics, interactive states, performance | No, regardless of creative mode |
| **B — Adaptable defaults** | Grid exactness, palette restraint, layout archetypes, motion character, typeface pairing | Yes, with a one-line stated reason |

- 1.1's pattern list now ships an explicit **escape hatch**: any "forbidden" pattern is fine if the brief calls for it — state the reason, don't avoid it reflexively
- 1.4's "no unfinished components" now distinguishes an *unlabeled* fake state (still banned) from an *explicitly labeled* out-of-scope item (now allowed)

Without this fix, an Experimental/Artistic/Freeform brief was structurally
fighting the same absolute rules as a Corporate one — v3's own Phase 2
intent table promised creative scaling that Section 1 never actually granted.

# 🎯 Style Exploration: From Convergence-by-Default to Convergence-by-Choice

## Before (v3)
- Phase 2 classified intent, Phase 4 selected style — nothing between them forced the model to consider more than one direction
- Section 8's scaffold was the path of least resistance: warned against in prose (1.1 enforcement note), but nothing in the *workflow* made reaching for it harder than reaching for an original direction

## Now (v3.5)
- **New Phase 2.5 — Style Exploration.** Before committing, sketch 2–3 distinct style directions (typeface family, palette character, layout archetype, motion character) in 2–4 sentences each; pick one and state why
- Mandatory for brand-defining surfaces or Premium/Artistic/Experimental/Playful/Freeform intent; explicitly skippable for small utilitarian components (see Scope Calibration below)
- This turns the 1.1 enforcement note from a *warning* into a *procedural requirement* — the scaffold can no longer be reached for by default because a divergent direction has already been sketched first

---

# 🧭 Scope Calibration: Right-Sizing the Workflow

## Before (v3)
- All six phases applied uniformly, whether the task was a full landing page or a single button variant
- No stated way to skip Phase 1's deep context analysis or a future Phase 2.5 for small, low-stakes requests — risk of over-applying a heavyweight process (and, in practice, of rules being followed superficially just to get through all six phases)

## Now (v3.5)
- **New Phase 2.6 — Scope Calibration**, run right after intent classification:

| Scope | What runs |
|-------|-----------|
| Full system (new surface, brand-defining screen) | All phases, including 2.5 |
| Single component inheriting an existing system | Skip 2.5 and most of Phase 1; inherit tokens; still pass Phase 6 in full |
| Quick iteration on prior output | Touch only the relevant tokens |

- Phase 6 (QA Gate) is never skippable at any scope — calibration reduces process weight, not the accessibility/state bar

# 🔢 Contrast Ratio: From Assertion to Formula

## Before (v3)
- 3.3 and 4.4 both instructed: "Contrast ratios are calculated, not asserted — state the actual computed ratio," and Phase 6 required the same
- No method was given anywhere in the file for *how* to compute it — a model following this rule had no way to produce a real number, only a plausible-sounding one

## Now (v3.5)
- 3.3 ships the actual WCAG algorithm: sRGB channel linearization → relative luminance → contrast ratio, as runnable pseudocode, with the AA/AAA thresholds (4.5 / 3 / 7 / 4.5) stated next to it
- Phase 6's contrast checkpoint now references this formula directly instead of repeating the unenforceable "calculate it" instruction

---

# 🕳️ Edge Cases & Error States (New Section 4.5)

## Before (v3)
- 1.3 banned placeholders and fake content but never defined what a *legitimate* empty state looks like, leaving "no empty states at all" as a plausible (wrong) reading
- No coverage anywhere of error states, loading strategy, destructive-action confirmation, or overflow/truncation — a "production-ready" deliverable could pass every v3 checkpoint while still shipping no error handling

## Now (v3.5)
- **New Section 4.5** explicitly separates legitimate empty states (first-use, zero-results — required UX) from lazy placeholders (still banned)
- Adds required coverage for: recoverable vs. unrecoverable errors, forms with >3 simultaneous errors, skeleton-vs-spinner loading strategy, offline/degraded data, destructive-action confirmation, and overflow/truncation strategy
- Phase 6 gains a matching checkpoint: every relevant edge state is either implemented or explicitly marked out of scope

# ✅ Phase 6 QA Gate: Two New Checkpoints

| # | New checkpoint | Closes |
|---|-----------------|--------|
| 1 | "Contrast ratios are computed using the formula in 3.3" | Replaces the unenforceable "calculate, don't assert" wording |
| 2 | "Every relevant edge/error/empty state is implemented or explicitly marked out of scope" | Closes the 4.5 gap |

The original ten checkpoints are unchanged; both new ones extend, not replace, the v3 gate.

---

# 🔍 What Did NOT Change

- Core philosophy (Section 0) and the five Prime Directives — unchanged (a sixth was appended, not substituted)
- Sections 3.1/3.2 numeric scales (8pt grid, 1.25 modular scale) — unchanged as *defaults*; only their framing shifted from absolute to Tier B
- Section 8's token values themselves — unchanged; only the disclaimer around when it's acceptable to use them as-is was sharpened
- Sections 4.1–4.4 (component definition, interactive states, button hierarchy, semantic HTML) — unchanged in substance
- Sections 5–7 (responsive engineering, performance, UX writing) — unchanged

# 🗑️ Removed / Reframed

| Item | Reason |
|------|--------|
| "BLOCKING LAWS" absolute framing on Section 1 | Replaced with Tier A/B split — accessibility stays blocking, visual conventions don't |
| 1.1 pattern list with no exceptions | Given an explicit escape hatch tied to brief justification |
| "Calculate contrast" with no method | Replaced with a stated formula |
| Six-phase workflow applied uniformly regardless of task size | Replaced with Scope Calibration (2.6) |
| Implicit assumption that "no placeholders" meant "no empty states" | 4.5 explicitly distinguishes the two |
