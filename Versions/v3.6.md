# 🛠️ UI Design Engineering v3.6 — Changelog

## The Evolution

v3.6 is not a rewrite. It is a **verifiability and coverage correction** of v3.5.

v3.5 fixed v3's uniform-strictness problem — it gave the skill a tiered
rulebook and a formula where there used to be an assertion. But writing
"calculate the contrast ratio" next to a formula doesn't guarantee the
formula gets *run*; it guarantees a plausible number gets produced either
way. And v3.5's own worked example — the Section 8 scaffold — shipped a
dark-mode block that silently dropped four semantic color tokens and both
shadow overrides, which is precisely the kind of gap Phase 6 exists to
catch. v3.6 closes the gap between "the rule is stated" and "the rule is
checkable," and fills the categories of interface work v3.5 didn't cover
at all.

The fundamental rule change:
> **v3.5:** "State the calculated value." **v3.6:** "Show the calculation that produced it — a number with no visible inputs is a guess, not a computation."

---

# 🐛 The Scaffold Bug: Dark Mode Wasn't Actually Engineered

## Before (v3.5)
- 3.3 stated: "Dark Mode ≠ Inverted Light Mode... maintain readable contrast, create depth via surface layers"
- Section 8's dark-mode block redefined backgrounds, text, borders, and accents — but `--success`, `--warning`, `--danger`, and `--info` were left undefined in the dark block, silently inheriting their light-mode values; `--shadow-sm` and `--shadow-md` were overridden but `--shadow-xs/lg/xl` were not
- Nothing in Phase 6 would have caught this, because no checkpoint asked whether dark-mode token *coverage* was complete — only whether contrast was "calculated" in general

## Now (v3.6)
- Section 8's dark-mode block now defines all four semantic colors independently (desaturated ~20–25%, lightened for dark surfaces per 3.3's own rule) and all five shadow tokens at higher opacity
- **New Phase 6 checkpoint:** "Every token that carries meaning in light mode... has an explicit dark-mode override — 'inherits the light value' is only acceptable if stated as a deliberate choice, never by omission"
- This is the closest thing to a hard bugfix in this version: the skill's own reference implementation no longer contradicts the rule it's supposed to demonstrate

---

# 🔢 Contrast Ratio: From Formula-Available to Calculation-Visible

## Before (v3.5)
- 3.3 shipped the real WCAG algorithm and Phase 6 required "the actual computed ratio," but nothing forced the *inputs* to be shown — a model could satisfy the letter of the checkpoint by writing a correct-looking ratio with no visible RGB values behind it

## Now (v3.6)
- Phase 6's contrast checkpoint now requires the intermediate values alongside the result: `(26,26,26) vs (255,255,255) → 16.1:1`, not just the final ratio
- A bare asserted number is explicitly redefined as a guess and fails the gate — "plausible" is no longer sufficient, "traceable" is the bar

---

# 🧭 Phase Ordering: Resolving the 2.5/2.6 Overlap

## Before (v3.5)
- Phase 2.5 (Style Exploration) listed its own "run when" triggers; Phase 2.6 (Scope Calibration) listed its own "skip when" conditions — for a case matching both (a new widget added to an existing dashboard: arguably "dashboard identity" *and* "single component"), the two phases gave no way to know which one governed

## Now (v3.6)
- 2.6 is now explicitly evaluated first, and wins ties: "if a request looks like it matches both a 2.5 trigger and a 2.6 skip-condition, 2.6 wins"
- A concrete disambiguation rule is added: a dashboard's first screen is a full system; a widget bolted onto an existing dashboard is a single component

# 🌍 Internationalization & RTL (New Section 5.1)

## Before (v3.5)
- Nothing in the skill addressed text direction, script variation, or content-length inflation across languages — a "production-ready" interface could pass every v3.5 checkpoint while being unusable in Arabic, Hebrew, German, or Thai

## Now (v3.6)
- **New Section 5.1**, Tier A when i18n is in scope, stated as an explicit exclusion when it isn't
- Requires logical CSS properties (`margin-inline-start`, not `margin-left`) over physical ones by default
- Requires directional icons to mirror in RTL while non-directional icons don't
- Requires containers to tolerate ~30–35% text-length inflation and non-Latin vertical rhythm
- Bans silently shipping LTR/English-only and letting it pass as general-purpose

---

# 📋 Forms at Scale: Dependencies and Data Loss

## Before (v3.5)
- 4.5 covered validation timing and error summaries for forms with >3 simultaneous errors, but said nothing about fields that depend on each other, or about losing user input to an accidental navigation

## Now (v3.6)
- 4.5 adds: field dependencies must be visible, not silent (disabled fields explain why; changing an upstream field re-validates or clears dependents rather than leaving stale invalid state)
- Adds: multi-step/long forms should persist draft state where the pattern implies it, and warn before an unsaved-change navigation away

---

# 📏 Quantifying What Was Previously Just Cited

## Before (v3.5)
- 3.6 invoked Miller's Law ("group information meaningfully") without a number attached — a model could label any grouping "chunked" and satisfy the rule
- Section 5 asked for support from 320px to 2560px+ with no concrete breakpoint steps in between

## Now (v3.6)
- Miller's Law now targets 5–9 items per group, with a rule to introduce sub-grouping or progressive disclosure past ~7
- Section 5 ships default breakpoint steps (375/390, 640, 768, 1024, 1280, 1536+) as Tier B — deviate when the content grid genuinely calls for it

# 🧪 Phase 6 QA Gate: New Checkpoints

| # | New checkpoint | Closes |
|---|-----------------|--------|
| 1 | Contrast checkpoint now requires visible intermediate values, not just a final ratio | Closes the "plausible number" loophole |
| 2 | Every light-mode-meaningful token has an explicit dark-mode override, or a stated exception | Closes the Section 8 scaffold bug directly |
| 3 | RTL/logical-properties check, or an explicit out-of-scope statement | Closes the i18n gap |
| 4 | Text-length and script-tolerance check | Closes the i18n gap |
| 5 | Mentally render the final code end-to-end before delivery — every referenced class/token resolves, markup nests validly, nothing references an undefined component or prop | New general-purpose sanity gate |

All prior v3.5 checkpoints are unchanged; five new ones extend, not replace, the gate.

---

# 🛡️ The Scaffold Disclaimer: Sharpened Again

## Before (v3.5)
- The Section 8 scaffold note said to treat it as "one candidate among the directions you sketch in Phase 2.5, not the thing you reach for first" — true in spirit, but didn't call out *which specific values* were placeholders

## Now (v3.6)
- The note now names the exact placeholder elements: "the accent blue, the neutral grayscale, and the sans-serif fallback stack... are functional placeholders, never a brand or identity decision" — and states plainly that shipping them unmodified for a full-system deliverable is itself an instance of the default-reaching Section 1.1 warns against

# 🔍 What Did NOT Change

- Core philosophy (Section 0) and the six Prime Directives — unchanged
- The Tier A/Tier B split introduced in v3.5 — unchanged in structure, only extended with new Tier A entries (i18n, dark-mode token parity)
- Phase 2.5 (Style Exploration) and its triggers — unchanged in substance, only its ordering relationship to 2.6 was clarified
- Sections 3.1/3.2 numeric scales, Section 3.4 motion rules, Section 3.7 data-viz rules — unchanged
- Sections 4.1–4.4 (component definition, interactive states, button hierarchy, semantic HTML) — unchanged
- Section 6 (Performance) and Section 7 (UX Writing) — unchanged
- Section 8's non-dark-mode token values (spacing, radius, light-mode colors, motion durations) — unchanged; only the dark-mode block and the disclaimer text around it were touched

# 🗑️ Removed / Reframed

| Item | Reason |
|------|--------|
| Dark-mode block missing 4 semantic tokens + 3 shadow tokens | Replaced with full parity coverage, independently tuned per 3.3's own dark-mode rule |
| "State the actual computed ratio" with no visibility requirement | Replaced with a requirement to show inputs, not just output |
| Ambiguous 2.5/2.6 overlap on brand-adjacent single components | Replaced with an explicit precedence rule and a worked disambiguation example |
| Miller's Law cited with no threshold | Replaced with a stated 5–9 range and a sub-grouping trigger |
| No i18n/RTL coverage anywhere in the skill | Replaced with new Tier-A Section 5.1 |
| No handling of form field dependencies or unsaved-navigation loss | Replaced with two new bullets in 4.5 |

Nothing from v3.5 was removed outright — every change in this version is
additive or corrective to something that was incomplete, silently buggy,
or unenforceable as written.
