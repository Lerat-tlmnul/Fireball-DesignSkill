# Master Prompting Guide: UI Design Engineering v5.6 · Liquid Glass · Agent

## Executive Overview

The **Agent edition** of UI Design Engineering v5.6 Liquid Glass does not ask a single model to write the whole site. It runs a team: one orchestrator, 10 coders (one file each), 5 testers and 5 reviewers. Deterministic gates run before any model judgment.

The result is a complete website whose navigation is a rounded Liquid Glass pill with real backdrop distortion (refraction), not just blur.

**What changes from the single-model edition**: the same design rules (§11 of the skill) and the same navigation rules, but a pipeline that tries several directions, repairs failures and keeps the best attempt.

---

## 1. System Architecture

### The Team

| Role | Count | Writes site files | Output |
|---|---|---|---|
| Orchestrator | 1 | no | Direction card, file ownership, attempts, scoring, final report |
| Coder | 10 | yes, one file each | The complete file, nothing else |
| Tester | 5 | no | Technical findings: T1 contrast, T2 syntax, T3 structure and a11y, T4 clean output, T5 motion budget |
| Reviewer | 5 | no | Judgment findings: R1 slop, R2 fit to brief, R3 nav behavior, R4 copy and voice, R5 responsive |

### File Ownership

| Coder | File | Job |
|---|---|---|
| C1 | index.html | Semantic structure, real content, section order |
| C2 | tokens.css | Tokens from the locked direction, light and dark modes |
| C3 | base.css | Reset, type scale, grid, focus, buttons |
| C4 | nav.css | Liquid Glass pill styles: invisible at top, visible on scroll |
| C5 | nav.js | Refraction (displacement map) and scroll state |
| C6 | hero.css | Hero composition with one signature move |
| C7 | sections.css | Sections and responsive layout |
| C8 | forms.css | Forms, errors, empty states |
| C9 | motion.css | Reveal, stagger, exits, reduced motion |
| C10 | main.js | Menus, reveal fallback, validation, no globals |

Coders run in parallel. Class and token names come from the direction card, never from another coder's output.

### Work Cycle

1. **Brief first.** If subject, audience or tone is missing, ask one question.
2. **Attempt (up to 3).** Each attempt uses a different direction: Warm paper, Civic clear, Local craft, Brutalist signal, Soft organic.
3. **Build.** The 10 coders write their files once, in parallel.
4. **Judge.** Deterministic gates run first, then testers and reviewers.
5. **Repair (up to 2 per attempt).** Each finding goes back to the coder that owns the file, who changes only what is named.
6. **Score.** A gate failure weighs 2 points, a judgment finding 1. Lower is better.
7. **Stop early** if an attempt has zero findings. Otherwise keep the best one.
8. **Report.** `REPORT.md` lists every attempt, the selected one and every open finding.

A wrong direction costs one attempt, not the whole build.

## 2. How to Write the Prompt

The prompt you pass to the orchestrator is the brief. The more precise it is about product, audience and tone, the fewer attempts the pipeline needs.

### Brief Template

```
### 1. PRODUCT CONTEXT
- Name and category: [e.g., "Atelier Roux, neighborhood artisan bakery"]
- Primary goal: [e.g., "Get customers to order online for pickup"]
- Target audience: [e.g., "Local residents, 25–60, mobile-first"]
- Primary action (CTA): [e.g., "Order for tomorrow"]

### 2. DESIGN INTENT
- Intent: [Professional | Premium | Playful | Editorial | Minimal | Dense | Artistic | Corporate | Futuristic]
- Theme: [Light | Dark | System adaptive]
- Reference principles: [e.g., "Notion's calm clarity, the warmth of a print magazine"]
- Visual guardrails: what it must NOT look like [e.g., "No centered hero, no purple gradients, no three identical cards"]

### 3. CONTENT (real, no placeholders)
- Primary content: [e.g., "Sourdough loaf €4.20, baked at 7am, pickup before 6pm"]
- Secondary content: [e.g., "Product list by category, opening hours, address"]
- Copy tone: [Warm | Factual | Technical | Minimal]

### 4. NAVIGATION
- Preset: [Subtle | Standard | Strong]
- Template: [Top (default) | Bottom (mobile app) | Side (documentation)]
- Links: [e.g., "Products, Hours, Visit, Order"]

### 5. TECHNICAL CONSTRAINTS
- Deliverable: static HTML/CSS/JS site
- Accessibility: WCAG 2.2 AA
- Motion: [e.g., "Subtle entrances, no looping animation"]
```

### What Makes a Brief Fail

- **No audience or subject**: the orchestrator asks a question, or produces a generic site that reviewers will reject (R1).
- **No content**: coders invent copy. Give real figures, product names and hours.
- **No guardrails**: the pipeline falls back to defaults (centered hero, three cards, logo strip, testimonials).
- **Contradictory intent** ("premium and playful"): pick one. One dominant intent, one secondary accent at most.

### Choosing a Navigation Preset

| Preset | Use when | Effect |
|---|---|---|
| **Subtle** | Text-heavy pages, busy photos, dense interfaces | Weak refraction, strong tint, maximum legibility |
| **Standard** | Default: brand sites, landing pages | Balance between effect and legibility |
| **Strong** | Playful surfaces over calm backdrops only | Pronounced refraction, avoid on busy backgrounds |

## 3. Running the Pipeline

```bash
AGENT_CMD=/path/to/your/agent node orchestrator.mjs ./site "brief"
```

- `AGENT_CMD` is the command that calls the models: it receives the role as an argument and the prompt on stdin, and returns the answer on stdout.
- **Without `AGENT_CMD`**, the pipeline runs offline: coders produce empty files and gates report them. This tests the plumbing, not a site.
- The `MODE` variable exists only in the solid edition. This edition is always Liquid Glass.

## 4. Deterministic Gates (before any model)

| Gate | Checks |
|---|---|
| T2 syntax | `node --check` on every JS file, brace balance in CSS, undefined tokens |
| T3 structure | `lang`, viewport meta, `alt`, one `h1`, no `div` acting as a button, every file wired in, nav present |
| T4 clean output | Forbidden patterns: lorem, TODO, console, section-label comments |
| T5 motion | At least 3 `@keyframes`, at least 4 animated declarations, reduced-motion rule, no layout-property transitions |
| R2 palette | Navy and violet background hues refused unless the brief asks for them |
| R3 nav | Pill radius, `backdrop-filter`, transparency fallback, scroll state |
| R3 distortion | `nav.js` must contain `feDisplacementMap`. Blur alone **fails** |

Gates decide pass or fail. Reviewers add judgment on top.

---

## 5. Design Rules (enforced by coders and reviewers)

- **Fit before style.** The style comes from the brief. No futuristic look by default (neon, glow, cyan or purple gradients, dark glass everywhere).
- **No AI slop.** Two or more signals (dark background with glowing gradient and glass cards; centered hero plus three feature cards plus logo cloud plus testimonial carousel; identical rounded cards; emoji as icons; hollow marketing words; invented stats) mean rework of layout, type, palette and material.
- **Identity.** One signature move, visible on the first screen, never captioned.
- **Clean output.** Only what a visitor should see: no section labels, version stamps or debug panels.
- **Limited Liquid Glass.** Glass is reserved for the navigation and at most one other floating layer.
- **Accessibility.** Text contrast 4.5:1, large text and UI boundaries 3:1, measured on the worst-case backdrop. Touch targets at least 44px.

## 6. Fixing an Output

The pipeline repairs itself. If the final result is still off, relaunch with a targeted correction rather than rewriting the whole brief.

### Problem: the site looks like a generic template

```
The report flags R1 (slop). Rebuild the layout and palette, not only the colour.
Keep intent [intent] and direction [direction name].
Replace the centered hero with an asymmetric composition. Reduce card uniformity.
```

### Problem: the navigation doesn't distort

Check the browser first. Only Chromium applies full distortion; other browsers keep blur glass. Then ask:

```
Verify that nav.js contains the feDisplacementMap filter and that lgSupported is true
on Chromium. If the filter is missing, redo C5 (nav.js) only.
```

### Problem: contrast fails

```
Run a WCAG 2.2 AA contrast audit on the nav text/surface pairs, at the worst-case
backdrop (white, black, most saturated colour). Adjust OKLCH lightness until 4.5:1
passes, and state the calculated ratio.
```

### Problem: a nav tint doesn't change

In the current files the tint is hard-coded in `nav.css` (`color-mix(... 62% ...)`), not driven by a variable. To change a preset, edit that percentage and the `scale`, `strength`, `bezel` and `blur` values passed to `liquidGlass()` in `nav.js`, one value at a time.

### Problem: placeholder text remains

```
Replace every generic text block with real content taken from the brief.
Do not deliver while any block contains lorem or a bracketed placeholder [ ].
```

## 7. Gate Troubleshooting

| Failure | Likely cause | Fix |
|---|---|---|
| T3: file not wired | A CSS or JS file isn't linked in `index.html` | Add the link or script, touch nothing else |
| T2: undefined token | A `var(--x)` has no definition in `tokens.css` | Define it in `tokens.css` (C2) |
| T5: not enough motion | Fewer than 3 keyframes or 4 animated declarations | Add animations on `transform` and `opacity` (C9) |
| R3: no distortion | `feDisplacementMap` missing from `nav.js` | Redo C5 with the full `liquidGlass()` function |
| Attempt dropped after 3 | No convincing direction | Sharpen the brief: intent, references, guardrails |

## 8. Checklist Before You Accept

- [ ] The brief states audience, product, intent and guardrails.
- [ ] Content is real: no lorem, no invented testimonials or logos.
- [ ] The nav is a rounded pill, invisible at top, visible on scroll.
- [ ] `nav.js` contains `feDisplacementMap`.
- [ ] Contrast is verified on the worst-case backdrop.
- [ ] The no-JS fallback keeps a visible surface.
- [ ] `prefers-reduced-transparency` and `forced-colors` give a solid surface.
- [ ] Every `var(--x)` and class is defined, every file is loaded.
- [ ] Motion budget met (3 keyframes, 4 declarations, reduced-motion rule).
- [ ] The signature move is visible on the first screen.
- [ ] `REPORT.md` has no open finding you are not willing to accept.

---

## 9. Limits

- At most 10 coders in parallel, and 10 testers or reviewers per judge round.
- At most 3 attempts and 2 repairs per attempt.
- A coder that returns anything other than a file counts as failed.
- Real rendering in Chrome is not included by default: mention it in the brief if you want it checked.

---

## Closing

This edition needs three things: a clear intent, real content and precise guardrails. The pipeline can try several directions and repair its own mistakes, but it cannot guess your product. The more concrete the brief, the fewer attempts are wasted.
