# UI Design Engineering v5.5 · Liquid Glass · Agent edition

**Team: 1 orchestrator, 10 coders, 5 testers, 5 reviewers.**
- The orchestrator runs the build: it locks the direction, assigns files, drives the repair loop and writes the final report.
- Each coder writes exactly one file.
- Testers verify with technical checks.
- Reviewers judge the result on substance: style, fit to the brief, navigation, copy, responsiveness.

This skill inherits the design rules of v5.5 (adapt to the brief, no futuristic default, no AI slop, clean output, WCAG 2.2 AA floor, OKLCH tokens, short reasoning). Read the v5.5 LG skill for the Liquid Glass details, presets and nav templates. This file defines who does what and how the parts fit together.

## 1. Team

| Role | Count | Writes site files | Output |
|---|---|---|---|
| Orchestrator | 1 | no | Direction card, file ownership, repair loop, final report |
| Coder | 10 | yes, one file each | The complete file, nothing else |
| Tester | 5 | no | Findings from technical checks: T1 contrast, T2 syntax, T3 structure and a11y, T4 clean output, T5 motion safety |
| Reviewer | 5 | no | Findings from judgment: R1 slop, R2 fit to brief, R3 nav behavior, R4 copy and voice, R5 responsive |

Rules for every agent:
- Reasoning is short and covers only decisions and risks (see v5.5 §0.3). No code in reasoning.
- Output format is fixed: a coder returns file contents only; testers and reviewers return `{"findings":[{"file","msg"}]}`, with `[]` when clean.
- A coder never edits a file it does not own. A tester or reviewer never edits anything.

## 2. File ownership (no write conflicts)

| Coder | File | Job |
|---|---|---|
| C1 | index.html | Semantic structure, real content, section order |
| C2 | tokens.css | Tokens from the locked direction, dark mode, identity hue |
| C3 | base.css | Reset, type scale, grid, focus, buttons with all states |
| C4 | nav.css | Liquid Glass nav styles, rounded, invisible at top |
| C5 | nav.js | Refraction and scroll state (presets from v5.5 LG) |
| C6 | hero.css | Hero composition |
| C7 | sections.css | Sections and responsive layout |
| C8 | forms.css | Forms, errors, empty states |
| C9 | motion.css | Reveal, stagger, exits, shimmer, reduced motion |
| C10 | main.js | Menus, reveal fallback, validation, no globals |

Coders run in parallel. A coder whose file depends on another (for example C1 needs class names) reads the locked class list from the orchestrator's direction card, not from another coder's output.

## 3. Pipeline

1. **Orchestrator: lock.** Write the direction card (5 lines: direction, type, palette hue, layout, nav template and preset). Every coder receives it verbatim.
2. **Build.** The 10 coders write their files once, in parallel.
3. **Gates (no model).** Run the deterministic checks:
   - syntax: `node --check` on every JS file, brace balance on every CSS file;
   - structure: `lang` on html, viewport meta, `alt` on images, one `h1`, no `div` acting as a button;
   - clean output: no lorem, TODO, console, debug or section-label comments;
   - motion safety: reduced-motion rule present, no layout-property transitions, transparency fallback present.
4. **Judgment.** The 5 testers and 5 reviewers run in parallel on the built files. Testers run the contrast script (v5.5 §10) and report numbers. Reviewers apply the slop test, the fit test, and the nav behavior, copy, and responsive checks.
5. **Repair (2 rounds maximum).** Each finding goes to the coder that owns the file, with the finding text and the current file. The coder changes only what the finding names.
6. **Report.** The orchestrator writes `REPORT.md`: phases, checks run, what is still open. Anything not executed is marked "not executed". Open findings are never hidden.

## 4. Liquid Glass checks (run by testers and reviewers)

- Nav is rounded in every state (top, scrolled, no-JS, mobile).
- Top state: surface invisible, brand, links and buttons visible, contrast passes on the worst-case hero backdrop.
- Scrolled state: contrast passes at `--lg-tint` on the worst-case backdrop; raise the tint, never drop the text contrast.
- No-JS state shows the surface. Non-Chromium browsers get blur glass that still looks intentional.
- `prefers-reduced-transparency` and `forced-colors` give a solid surface.
- At most two Liquid Glass surfaces on the page.

## 5. Model boundary

The orchestrator calls models through one function, `runAgent(role, prompt)`. In the shipped file it reads the environment variable `AGENT_CMD`, which points to any command that takes the role on argv and the prompt on stdin, and prints the answer on stdout. Without `AGENT_CMD`, it runs offline: the coders produce empty files and the gates report them. This is intentional: it proves the pipeline works before a model is connected.

## 6. Process limits (protect the budget)

- Coders in parallel: 10 maximum per round. Testers and reviewers: 10 maximum per round.
- Repair: 2 rounds maximum. After that, stop and report.
- A coder that returns something other than a file (JSON, commentary, empty output) is treated as failed and re-run once.

## 7. Files shipped with this skill

- `orchestrator.mjs`: the runnable orchestrator, gates included. Usage: `node orchestrator.mjs ./site "Standard preset, Top nav"`. Set `AGENT_CMD` to connect a model.
- `v5.5-LiquidGlass-skill.md`: the design rules, presets, and nav templates used by coders C4 and C5.
