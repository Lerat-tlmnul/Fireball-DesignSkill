# UI Design Engineering v5.6 · Liquid Glass · Agent edition

**Team: 1 orchestrator, 10 coders, 5 testers, 5 reviewers.**
- The orchestrator runs the build: it locks the direction, assigns files, drives the repair loop, keeps the best attempt and writes the final report.
- Each coder writes exactly one file.
- Testers verify with technical checks.
- Reviewers judge the result on substance: style, fit to the brief, navigation, copy, responsiveness.

## 1. Team

| Role | Count | Writes site files | Output |
|---|---|---|---|
| Orchestrator | 1 | no | Direction card, file ownership, attempts, scoring, final report |
| Coder | 10 | yes, one file each | The complete file, nothing else |
| Tester | 5 | no | Technical findings: T1 contrast, T2 syntax, T3 structure and a11y, T4 clean output, T5 motion budget |
| Reviewer | 5 | no | Judgment findings: R1 slop, R2 fit to brief, R3 nav behavior, R4 copy and voice, R5 responsive |

Rules for every agent:
- Reasoning is short and covers only decisions and risks. No code in reasoning.
- A coder returns file contents only. Testers and reviewers return `{"findings":[{"gate","file","msg"}]}`, with `[]` when clean.
- A coder never edits a file it does not own. A tester or reviewer never edits anything.

## 2. File ownership (no write conflicts)

| Coder | File | Job |
|---|---|---|
| C1 | index.html | Semantic structure, real content, section order |
| C2 | tokens.css | Tokens from the locked direction, dark and light modes, identity hue |
| C3 | base.css | Reset, type scale, grid, focus, buttons with all states |
| C4 | nav.css | Liquid Glass nav styles: rounded pill, invisible at top, visible on scroll |
| C5 | nav.js | Refraction and scroll state (`data-scrolled`) |
| C6 | hero.css | Hero composition with one signature move |
| C7 | sections.css | Sections and responsive layout |
| C8 | forms.css | Forms, errors, empty states |
| C9 | motion.css | Reveal, stagger, exits, shimmer, reduced motion |
| C10 | main.js | Menus, reveal fallback, validation, no globals |

Coders run in parallel. Class and token names come from the direction card's contract, never from another coder's output.

## 3. Branch and select (not a straight line)

1. **Brief first.** If the brief is missing (subject, audience, tone), ask one question. Never build from nothing.
2. **Attempt (up to 3).** Each attempt uses a different direction. A direction is not reused until all are tried.
3. **Build.** The 10 coders write their files once, in parallel, from the direction card.
4. **Judge.** Gates run first (deterministic). Then testers and reviewers run in parallel.
5. **Repair (up to 2 per attempt).** Each finding goes to the coder that owns the file. The coder changes only what the finding names. Re-judge after each repair.
6. **Score.** Gate failures weigh 2 points, judgment findings weigh 1. Lower is better.
7. **Stop early** if an attempt has zero findings. Otherwise keep the best-scoring attempt.
8. **Report.** `REPORT.md` lists every attempt, the selected one, and every open finding. Open findings are never hidden.

A wrong direction costs one attempt, not the whole build.

## 4. Direction card (locked per attempt)

Five lines, sent verbatim to every coder: direction name, type pair, palette hue and accent logic, layout and hero archetype, nav preset. The list of class and token names is part of the card.

Directions are tried in order: Warm paper, Civic clear, Local craft, Brutalist signal, Soft organic. None uses a navy or violet background by default.

## 5. Hard rules

- **No default navy.** Background tokens may not sit in the 225 to 290 hue range unless the brief names it. Gate R2.
- **Liquid Glass nav is required.** Rounded pill (`border-radius` 9999px or equivalent), `backdrop-filter`, scroll state, and fallbacks under `prefers-reduced-transparency` and `forced-colors`. Gate R3.
- **The nav must be wired in.** The nav element exists in `index.html`, every CSS file is linked, every JS file is loaded, and `nav.js` applies the glass effect. Gate T3 (integration).
- **Motion budget.** At least 3 `@keyframes`, at least 4 animated declarations, a reduced-motion rule, and no layout-property transitions. Gate T5.
- **Identity on the first screen.** At least one strong accent or two hue families above the fold. Judged by R1.
- **Glass only on the nav and at most one more floating layer.** Judged by R1.
- **One contract.** Every `var(--x)` and class used in the HTML is defined. Gate T2.
- **Clean output.** No lorem, TODO, console, debug or section-label comments. Gate T4.

## 6. Gates (deterministic, run before any model)

- T2 syntax: `node --check` on every JS file, brace balance on every CSS file, undefined tokens.
- T3 structure and integration: `lang`, viewport meta, `alt`, one `h1`, no `div` acting as a button, every file wired in, nav element present.
- T4 clean output: forbidden patterns.
- T5 motion budget: keyframes, animated declarations, reduced-motion rule, no layout transitions.
- R2 palette: banned hue range on background tokens.
- R3 Liquid Glass nav: backdrop filter, pill radius, transparency fallback, scroll state.
- R3 distortion: `nav.js` must contain the displacement map (`feDisplacementMap`). Blur alone is not Liquid Glass and fails the gate.

Gates decide pass or fail. Reviewers add judgment on top.

## 7. Liquid Glass nav reference

- **Shape.** Rounded pill, always. The refraction follows the rounded shape.
- **Presets.** Subtle (scale 22, strength 0.6, bezel 14, blur 1, tint 70%) for text-heavy or busy pages. Standard (scale 34, strength 1.0, bezel 18, blur 2, tint 62%) as default. Strong (scale 42, strength 1.2, bezel 24, blur 3, tint 56%) only for playful surfaces over calm backdrops. Never above scale 44 or below tint 52%.
- **Distortion is mandatory.** The rim of the pill bends the backdrop. Blur alone is not Liquid Glass. The reference `reference-site/nav.js` contains the full `liquidGlass()` function.
- **Refraction.** Chromium applies an SVG displacement map to the backdrop only, built from the element's own size and radius. Other browsers keep blur glass. Text and icons are never filtered.
- **Top state.** The surface is invisible; brand, links and buttons stay visible. Contrast is computed against the worst-case hero backdrop.
- **Scrolled state.** The surface fades in on `opacity` only. Contrast passes at the tint on the worst-case backdrop.
- **Templates.** Top pill (default), bottom dock, side rail. Each keeps the same rules.
- **No-JS.** The surface stays visible.
- **Fallbacks.** Solid surface under `prefers-reduced-transparency`, `forced-colors`, and no `backdrop-filter` support.
- **Performance.** The displacement map is redrawn at most once per frame, and only while visible.

Reference markup and CSS: `reference-site/` in the orchestrator folder.

## 8. Model boundary

`runAgent(role, prompt)` is the only place a model is called. It runs the command in `AGENT_CMD`, passing the role on argv and the prompt on stdin, and reads the answer on stdout. Without `AGENT_CMD`, it runs offline: coders produce empty files and gates report them. This proves the pipeline works before a model is connected.

## 9. Limits

- At most 10 coders in parallel per attempt, and 10 testers and reviewers per judge round.
- At most 3 attempts and 2 repairs per attempt.
- A coder that returns anything other than a file is treated as failed.

## 10. Files

- `orchestrator.mjs`: runnable orchestrator with all gates. Usage: `AGENT_CMD=/path/to/agent node orchestrator.mjs ./site "brief"`.
- `reference-site/`: passes every glass-mode gate, with a wired-in Liquid Glass nav.

## 11. Design rules (shared by both editions, identical text)

These rules apply to every coder and reviewer, in both editions.

**Fit before style.** The style comes from the brief: industry, audience, tone, existing brand. Never pick a futuristic look (neon, glow, cyan or purple gradients, dark glass everywhere) by default. Use it only if the user asks, and keep it restrained.

**No AI slop.** A page fails if it could have been generated for any other brief. Slop signals: dark background with a glowing gradient and glass cards without a brief reason; centered hero plus three feature cards plus logo cloud plus testimonial carousel; identical rounded cards everywhere; emoji as icons; marketing filler ("Revolutionize", "Seamless", "Unleash", "AI-powered"); invented stats. Two or more signals means rework the layout, type, palette and material, not only the colour.

**Identity.** One signature move per site, visible on the first screen, never captioned on the page. At least one strong accent or two hue families above the fold.

**Clean output.** The shipped page contains only what a visitor should see. No section labels, version stamps, swatches, debug panels, state galleries, placeholder tags, or design commentary in markup or comments. Eyebrow labels and pill badges only when they carry real information.

**Type.** Pair fonts for contrast of character, not only weight. Fluid display sizes with `clamp()`. Body 45 to 75 characters per line. Real fallback stacks for every font.

**Colour.** OKLCH tokens. Neutrals tinted toward the brand hue. Separate fill colours from text colours (`--success` and `--success-fg`). Dark mode is engineered, not inverted. Colour is never the only signal.

**Motion.** Every animation explains a relationship, gives feedback, guides attention or sets mood. Timing by role: 150 to 250ms for buttons, 300 to 500ms for sections, 500 to 800ms for screen entrances. Ease-out by default, ease-in for exits, linear only for loops. Animate `transform` and `opacity`; never layout properties on in-flow elements. Reduced motion removes movement and keeps gentle fades.

**Accessibility floor (WCAG 2.2 AA).** Text contrast 4.5:1, large text and UI boundaries 3:1, computed against the worst-case backdrop. Real buttons and links, labels on inputs, headings in order, `lang` on html, alt text, visible focus, touch targets at least 44px, focus never hidden by sticky UI.

**Writing.** Buttons say what happens ("Save changes"), not "Submit". Empty states and errors give a next step. No Lorem Ipsum, no invented testimonials or logos.

**Reasoning.** Short. Decisions and risks only. No code written in reasoning.
