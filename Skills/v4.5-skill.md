# UI Design Engineering v4.5

Three jobs, in this order: **(1) ship only what the visitor should see;
(2) make something that could only have been made for this brief; (3) make sure
it works for everyone.** Jobs 1 and 3 are a hard floor (Tier A). Job 2 is where
the skill pushes you *away* from safe defaults and away from your own last
output.

**Prime directives**
1. Beautiful but unusable = failure. Usable but forgettable = also failure.
2. **The shipped page contains content and interface, nothing else.** No labels, badges, notes, or test panels that talk about the design, the process, or the AI (§1, Clean Output).
3. A rule broken on purpose, with a one-line reason, is design. A rule broken by accident is a bug.
4. Never ship generic when a point of view was available. Never ship the same site twice. Never ship inaccessible, ever.
5. Ship real code and real content. No prototypes dressed up as finished work.
6. Never claim a check passed unless you actually ran it. Say "not executed" instead.

## 1. Two tiers

### Tier A — the floor (never negotiable, whatever the creative mode)

**Clean Output (what ships is what the visitor sees)**
- **No parasitic information.** Banned in the page, visible or not: section labels ("Hero", "Features", "Section 2"), version stamps, "Built with…", "Design by AI", direction names, signature-move captions, deviation notes, token or color swatches, contrast badges, state galleries, grid/debug overlays, placeholder tags ("Your text here"), instructional captions, TODO text, `console.log`.
- **Eyebrow rule.** Small label lines above headings ("01 — Features", "Why us", "Our process") are the #1 parasite. Allowed only when they carry real information the visitor needs (a real category, date, place, price, step number in a true sequence). Same for pill badges ("New", "Beta", "✨ AI-powered"), decorative numbering, "Scroll" hints, and emoji used as icons.
- **Testing parts only on request.** Test pages, QA panels, state showcases, contrast tables, Storybook-style galleries, `?debug` modes: build them only if the user asks, in a **separate file**, never inside the shipped page.
- **Process stays in chat, short.** The Direction Card (§2, Phase 4) and the Deviation ledger go in the chat reply, never in the page or its comments. Components and quick iterations get no card. QA runs silently: report nothing if all passed, one line if something is "not executed" or was fixed. No victory recap, no feature list restating the code.
- **Code comments**: only for a non-obvious *why*. No section banners, no design commentary.

**Accessibility floor**
- **Contrast** computed with the script in §10 (text 4.5:1, large text 3:1, UI boundaries / focus rings / meaningful icons 3:1). Show the numbers in chat only when asked or when a pair is borderline. Glass surfaces are computed against the **worst-case backdrop** they can sit on.
- **Semantics + keyboard**: real `<button>`, `<a>`, `<label>`, headings in order, landmarks, `lang` on `<html>`, alt text. Everything operable by keyboard, visible `:focus-visible`.
- **WCAG 2.2 additions**: focus not hidden by sticky UI (2.4.11, use `scroll-padding`); targets ≥ 24×24px minimum (2.5.8) and ≥ 44×44px on touch; no drag-only interactions (2.5.7); no re-asking known info (3.3.7); no cognitive-test login, allow paste and password managers (3.3.8); reflow at 320px (1.4.10).
- **States**: hover (only under `@media (hover: hover)`), focus-visible, active, disabled, loading (if async). Error/empty/overflow per §5.2.
- **Color is never the only signal** (icon + text + color).
- **Motion safety**: honor `prefers-reduced-motion`; never animate layout properties of in-flow elements (`width`, `height`, `top`, `left`, `margin`); the fixed nav (§9.1) is the one documented exception because it is out of flow; no flashing > 3 times/second.
- **Transparency safety**: every glass/blur surface has a solid fallback for `@supports not (backdrop-filter)`, `prefers-reduced-transparency: reduce`, and `forced-colors: active`.
- **Forced colors**: nothing essential disappears under `forced-colors: active` (use `outline`, not only `box-shadow`, for focus).
- **Text resizes**: type in `rem`, layout survives 200% zoom.
- **Honest content**: no Lorem Ipsum, no fake stats or testimonials, no fake logos. Real empty states are required UX, not filler.
- **i18n stated**: logical CSS properties by default; if RTL/translation is out of scope, say so in one line in chat.

### Tier B — adaptable defaults (bend them freely, log it in chat)
Grid exactness, 8pt rhythm, modular scale, 60/30/10 palette, 12-col grid, card
systems, radius uniformity, easing conventions, one-accent restraint, "clean"
whitespace, the default navigation (§3.6). These exist to stop *accidental*
choices, not to cap ambition. Break any of them when the direction calls for it
and record it in the **Deviation ledger** (§2, Phase 4): `Rule → what I did
instead → why`.

## 2. Workflow

### Phase 0: Scope (decide first, say it in one line)
- **Full surface** (landing, website, dashboard first screen, app shell, brand-defining page): all phases.
- **Single component in an existing system**: inherit tokens, skip Phases 3 and 4, still pass Phase 7.
- **Quick iteration** ("punchier", "darker", "try another"): touch only the tokens and levers concerned; don't re-derive everything.
If a request fits both full and narrow scope, the narrower one wins unless the brief establishes a new surface.

### Phase 1: Context (short, not a questionnaire)
Who uses it, on what device, doing which job; category norms; the one metric or action that matters; 3-second emotional target. Read the brief and any references before asking anything. Ask **one** question only if the answer would change the direction materially; otherwise state your assumption and proceed.

### Phase 2: Intent + Ambition dial
Pick an intent: Professional · Premium · Futuristic · Experimental · Playful · Corporate · Artistic · Minimal · Dense · Editorial · Freeform.
Then set the **Ambition dial** (1–5) and state it:

| Dial | Meaning | Typical use |
|---|---|---|
| 1 | Invisible craft, inherit everything | Component in a mature system |
| 2 | Refined, conventional | Internal tools, admin, dense data |
| 3 | Distinctive within category norms | SaaS product UI, e-commerce |
| 4 | Art-directed, memorable | Landing pages, brand sites, marketing |
| 5 | Expressive, rule-breaking with purpose | Portfolios, campaigns, culture/music/fashion/games |

Defaults: marketing surface → 4, product UI → 3, dense tool → 2. User words override: "surprise me", "be bold", "no constraints", "wow" → 5, no clarifying question. The dial changes how many Tier B rules you bend, never Tier A.

### Phase 3: Divergence + Variety roll (mandatory for full surfaces at dial ≥ 3)
1. **Roll** (§3.5): pick a starting point for each lever from the pools instead of reaching for your habit. Then sketch **three directions** in 2–3 sentences each. They must differ on **at least four of seven levers**: type, palette hue family, layout archetype, hero archetype, material, motion, navigation. **At least one must be unexpected for the category.**
2. **Anti-repeat**: never reuse the previous direction, font pairing, hero, or layout archetype of this conversation. Two sites in the same conversation differ on ≥ 4 levers.
3. Pick one and say why in one line, or hand the choice to the user when stakes are high. Skip when scope is a component or a quick iteration, and say so.

### Phase 4: Lock the Direction Card (in chat, ≤ 6 lines, before the code, full surfaces only)
```
Direction: <name> | Big idea: <one sentence>
Type: <display + text, fallbacks>   Palette: <hue family, chroma, accent logic>
Layout: <archetype> | Hero: <archetype> | Nav: <variant>
Material: <flat / paper / grain / hard-shadow / glass-with-purpose>   Motion: <personality>
Signature move: <the one memorable, ownable detail>
Deviation ledger: <Tier B rules bent → why>
```
The **signature move** is the thing someone would describe to a friend: an oversized running headline, a cursor-reactive grid, a nav that behaves like a table of contents, data labels set as marginalia. One per surface. It must pass Tier A and it is **never captioned on the page**.

### Phase 5: Blueprint (structure before skin)
Information hierarchy (primary / secondary / tertiary), user flow (discover → understand → decide → act → feedback → return), scanning pattern (F for reading, Z for landing), real content length and data shape, navigation model, grid and density. Analyse real text and data before laying anything out: the interface adapts to content, not the reverse. Every section earns its place with content the visitor needs; cut any section that exists only to fill a template.

### Phase 6: Build
Use the locked direction. Tokens first (§9 shows the format), then layout, then components with all states, then edge states. Navigation defaults to §3.6 / §9.1. Prefer modern CSS (§4.6) with graceful fallback. Output must *behave* correctly, not just look right, and must pass Clean Output.

### Phase 7: QA gate (before delivery, silent)
Split honestly into what a script can prove and what needs judgment. Fix, then deliver; report only per §1 (Process stays in chat, short).

**Checkable (run it if you have a sandbox; otherwise trace by reading and mark "not executed")**
- [ ] **Clean Output scan**: no banned label, badge, eyebrow without real info, debug/test block, swatch, or design commentary in markup, comments, or `console`
- [ ] Every foreground/background pair used was computed with §10 (glass: worst-case backdrop)
- [ ] Every `var(--x)` used is defined; every meaningful light token has a dark override
- [ ] No `<div>`/`<span>` acting as button, link, or input; every input has a label
- [ ] No in-flow layout-property animation; `prefers-reduced-motion`, `prefers-reduced-transparency`, `forced-colors` blocks present
- [ ] `lang`, viewport meta, `alt`, heading order, landmarks present
- [ ] No Lorem Ipsum, no fake data presented as real
- [ ] Nav: top state, scrolled state, mobile menu, Escape/focus return, 44px targets, solid fallbacks all work
- [ ] Rendered mentally end-to-end: markup nests validly, nothing references an undefined class, prop, or token

**Judgment (answer each in your head, fix before shipping)**
- [ ] **Swap test**: replace the brand name with a competitor's. Does anything break? If not, it is generic. Push the direction further.
- [ ] **Twin test**: could this be mistaken for the last site you made? If yes, re-roll two levers.
- [ ] **Squint test**: blur the screen. Is the primary action still the strongest element?
- [ ] **Grayscale test**: does hierarchy survive without color?
- [ ] **Category test**: would this be mistaken for a typical competitor? Intended only if the brief says so.
- [ ] **Skeleton test**: if the tokens equal the §9 skeleton unmodified on a full surface, you skipped Phases 3–4.
- [ ] **Noise test**: cover each small text element: if the page loses nothing, delete it.
- [ ] Signature move present, visible, harmless to usability
- [ ] Edge states (§5.2) implemented or explicitly marked out of scope
- [ ] Layout holds with +35% text length and a non-Latin script

## 3. Creative toolkit

### 3.1 The seven levers (each one is a place to make a decision, not take a default)
- **Type.** Pair for contrast of *character*, not just weight. Use scale jumps ≥ 1.5× between display and body when the direction wants drama. Exploit variable axes (`opsz`, `wdth`, `wght`, `SOFT`) as expression. Tabular numerals for data. Never ship the system fallback as an identity.
- **Color.** Tint your neutrals toward the brand hue (chroma 0.005–0.03) instead of dead gray. Shift hue slightly in shadows and highlights. Allow one deliberately "wrong" color. Use `color-mix(in oklch, …)` for ramps. Gradients need a reason (light source, depth, data), not decoration.
- **Composition.** Asymmetry, overlap, a single element that breaks the grid, extreme scale contrast, deliberate density changes between sections. Whitespace is a material; spend it unevenly.
- **Hero.** The first screen is its own decision (pool in §3.5), not "centered title + button".
- **Material.** Flat ink, paper and grain (inline SVG `feTurbulence` as a data URI), hard offset shadows, hairline rules, halftone, frosted glass **only** where layering has meaning (the nav is the default place). Pick one main material and commit.
- **Motion.** A personality, not an effect: snappy (steps, ≤ 150ms), editorial (slow fades and clip-path reveals), luxe (500–700ms ease-out), playful (springs, ±2° tilts), instrument (≤ 120ms, no flourish). Choreograph with stagger and shared axes; one orchestrated entrance beats ten scattered hovers.
- **Voice.** Microcopy, empty states, and errors share the direction's tone. Tone is part of the design.

### 3.2 Direction seeds (starting points to combine, mutate, or ignore)
Fonts named are Google Fonts families; always give a real fallback stack, `font-display: swap`, and self-host or load responsibly. If a family can't be loaded, say what fallback you used.

1. **Editorial Warm**: Fraunces or Newsreader + a clean grotesk; paper neutrals tinted hue 70–90, terracotta or ink-blue accent; asymmetric columns, pull-quotes at 5–8× body size, hairline rules; slow `clip-path` text reveals.
2. **Brutalist Signal**: Archivo at wide/black or a heavy mono; zero radius, 2px borders, hard offset shadows, visible grid; off-white or black with one screaming signal color; instant or stepped motion.
3. **Luxe Nocturne**: light-weight serif display with wide-tracked caps labels; dark surfaces tinted hue 280–300 at chroma ≤ 0.02, a muted metallic accent (≈ `oklch(0.78 0.09 85)`); huge spacing; 500–700ms ease-out; restrained parallax.
4. **Technical Instrument**: mono for data + a neutral grotesk for UI; 1px borders, radius 2–4px, tabular numerals, keyboard-first affordances, command palette; one accent plus status colors; ≤ 120ms motion.
5. **Playful Pop**: rounded or quirky grotesk (Bricolage Grotesque, Unbounded); 3 saturated hues at matched lightness, radius 20–28px, sticker borders, slightly tilted elements, spring easing.
6. **Calm Workspace**: humanist sans + a quiet serif accent; low-chroma tinted neutrals, generous line-height, almost no shadow; motion barely there.
7. **Data Poster**: oversized numerals and labels as the hero, charts as graphic design, 2-color system, tight leading, annotations like a newspaper graphic.
8. **Neo-Swiss Grid**: one grotesk in two weights, strict visible columns, flush-left ragged-right, red or cobalt as the only color, huge numerals as navigation; motion limited to alignment snaps.
9. **Risograph Zine**: two spot colors with `mix-blend-mode: multiply` overlap, halftone dots, slight misregistration offsets, condensed display + typewriter text, rotated stickers, tape and torn-edge SVG masks.
10. **Soft Organic**: warm off-whites, moss/clay/sand palette, blob and pebble shapes via `border-radius` and SVG paths, rounded serif display, slow floating motion at tiny amplitude, photography with soft masks.
11. **Cinematic Dark**: full-bleed media, subtitle-style captions, letterbox bars, one amber or teal accent, slow dolly-style scale on scroll (`transform` only), huge condensed display (Big Shoulders Display, Anton-like).
12. **Blueprint**: deep blue or cream "drafting paper" ground, hairline construction lines, dimension marks and callout leaders as layout, mono labels that are *real data*, drawing-in SVG paths on load.
13. **Terminal Retro**: mono everywhere, phosphor green/amber on near-black or inverted paper, box-drawing borders, blinking caret (respect reduced motion), command-palette as primary navigation.
14. **Maximal Collage**: overlapping cut-out images, mixed type families used deliberately, clashing-but-balanced palette at matched lightness, sticker UI, overflow hidden with intent. Needs dial 5 and a stricter Tier A pass.
15. **Quiet Japanese Minimal**: extreme whitespace (ma), one vertical text element, ink black + vermilion seal accent, thin serif, very slow fades, grid-less asymmetry.

Mixing is encouraged: take the type of one, the material of another.

### 3.3 Anti-defaults (avoid by habit, allowed by reason)
Centered hero + gradient mesh + three feature cards + logo cloud + testimonial carousel · purple-to-blue diagonal gradients · blur-on-everything glass · identical cards with uniform shadow and radius · Inter or system-ui as the unexamined identity · Lucide outlines with no optical adjustment · eyebrow label on every section · gradient text on every heading · emoji as icons · stats band with invented numbers · the same layout across fintech, gaming, luxury, edu, music. If the brief wants one of these, say why in chat and proceed.

### 3.4 Reading references
Extract the *logic*, never the pixels. Apple → intentional spacing and product storytelling, not white rounded cards. Stripe → technical confidence, controlled gradients. Linear → density and keyboard-first precision. Notion → calm, content priority. Gaming → contrast and fast feedback. Luxury → restraint and slow motion. Brutalist → visible structure, rules broken with purpose.

### 3.5 Variety engine (pools to roll from)
**How to roll.** Models drift to the same few choices. For each lever below, take `index = (character count of the brief) mod (pool size) + offset`, with offset 0 for type, 1 for palette, 2 for layout, 3 for hero, and so on, and step forward until the pick is not absurd for the brief. A weird-but-defensible pick beats a safe one. Never take the first item by habit.

**Layout archetypes**: asymmetric split with oversized type · bento grid with varied cell sizes · magazine columns · sticky-stack storytelling · index list as the hero (big rows, hover preview) · full-bleed media with overlaid type · 50/50 split with one sticky half · poster / typographic wall · vertical timeline spine · dashboard-first · overlapping collage · horizontal scroll chapter (with keyboard and vertical fallback) · centered monolith (minimal, one column) · diagonal or stepped sections.

**Hero archetypes**: oversized type alone · product shown in context · interactive toy (cursor-reactive grid, drag-free) · marquee statement · split typography/image · command-palette hero · live real-data hero · single-sentence manifesto · image mosaic · scroll-driven reveal of the headline · video or looping CSS animation behind restrained type.

**Section archetypes (use real content only)**: sticky scroll steps · big numerals with real figures · comparison table · accordion FAQ · pricing with a real toggle · masonry gallery · quote wall of real quotes · timeline · CTA band with one action · tabbed showcase · before/after slider (keyboard operable) · map or schedule.

**Palette recipes (hue families, verify contrast)**: bone + cobalt · moss + cream + clay · ink + tangerine · plum dusk + pale pink · sand + terracotta + deep green · graphite + amber · deep teal + coral · off-white + signal lime on black · rosewood + butter yellow · navy + warm paper. Avoid purple→blue diagonal gradients as an identity.

**Font pairings (Google Fonts)**: Instrument Serif + Geist · Bricolage Grotesque + Literata · Syne + DM Sans · Familjen Grotesk + Spectral · Unbounded + Manrope · Archivo + JetBrains Mono · Young Serif + Outfit · DM Serif Display + DM Sans · Space Mono + Rethink Sans · Gloock + Schibsted Grotesk · Anybody + IBM Plex Sans · Big Shoulders Display + Barlow · Fraunces + Work Sans · Newsreader + Geist.

**Backgrounds and surfaces**: grain · dot grid · blueprint grid · topographic lines (inline SVG) · halftone · soft radial light source · solid color blocks · paper texture · subtle noise-masked gradient (one light source). Pick one.

### 3.6 Navigation (default: morphing rounded glass pill)
**Default behavior (Tier B, log it if you change it):**
- The nav is a **rounded pill** (`--radius-full` or a generous radius), floating `--space-4` from the top, centered, never edge-to-edge.
- **At the top of the page it is large**: more vertical padding, wider, larger brand mark, near-solid surface so it reads cleanly over the hero.
- **When the user scrolls down it becomes glassmorphism and stays rounded**: more compact, narrower, translucent tint + `backdrop-filter: blur() saturate()`, soft shadow. Back at the top, it expands again.
- The glass tint stays opaque enough that text keeps ≥ 4.5:1 on the **worst-case backdrop**; solid fallbacks for no blur support, `prefers-reduced-transparency`, and forced colors.
- Targets stay ≥ 44px in both states; on mobile the links collapse into a menu button with a proper disclosure (`aria-expanded`, Escape closes and returns focus).
- Drive the state with an `IntersectionObserver` sentinel (no scroll listeners). Without JS, the page simply keeps the top state.
- Reference implementation: §9.1.

**Variants to roll when the direction asks for something else**: centered logo with split links · floating dock (bottom on mobile) · command-bar nav (`/` or ⌘K opens search + links) · side rail with vertical labels · table-of-contents nav that highlights the current section · pill with a thin scroll-progress line inside · hide on scroll down, reveal on scroll up (keep focus reachable). Whatever the variant, the morph idea (large at rest, compact when scrolling) is worth keeping.

### 3.7 Interaction delights (pick at most three per surface; all behind Tier A)
Cursor spotlight on cards (`@media (hover: hover) and (pointer: fine)`) · magnetic buttons (≤ 8px shift) · scroll-linked progress line · line-by-line text reveal · number counters (final real value is in the markup, animation only decorates) · View Transitions between pages · pausable marquee · sticky stacking cards · subtle parallax via `animation-timeline` in `@supports` · branded `::selection` and scrollbar (`scrollbar-color`) · image preview following hover on list rows · tilt cards (≤ 6°). Each one disappears cleanly under `prefers-reduced-motion` and on touch. None may be captioned or explained on the page.

## 4. System specs (defaults you may bend)

### 4.1 Spacing *(Tier B)*
Default scale: 4 · 8 · 12 · 16 · 24 · 32 · 48 · 64 · 96 · 128 · 160px. The scale exists so numbers are never accidental; `17px` is fine when you can say why. Small gaps connect related items, medium separate groups, large separate sections. Use `rem` for anything tied to text size.

### 4.2 Typography *(Tier B for ratios, Tier A for resizability)*
Default modular scale 1.25 from 1rem: 0.75 · 0.875 · 1 · 1.25 · 1.5625 · 1.9375 · 2.4375 · 3.0625 · 3.8125 · 4.75rem. Switch ratio per intent (1.2 calm, 1.333 confident, 1.5+ dramatic). Body 45–75ch (`max-width: 65ch`), line-height body 1.5–1.65, headings 1.05–1.2, dense UI 1.2. Large headings tracking −0.02em. `text-wrap: balance` on headings, `pretty` on paragraphs. Fluid display type with `clamp()`.

### 4.3 Color *(OKLCH; contrast is Tier A)*
- Define tokens in OKLCH. Hex is only a tooling fallback.
- **Separate fills from text colors for semantics.** A green that works as an icon fill rarely passes as text; ship `--success` (fill) and `--success-fg` (text).
- Separate `--accent` (fills, with `--on-accent` text) from `--accent-text` (accent used *as* text on light surfaces).
- UI boundaries (inputs, checkboxes) need `--border-control` at ≥ 3:1, distinct from the decorative `--border-default`.
- Dark mode is engineered, not inverted: no pure `#000`, lower chroma ~20–30%, depth from surface layers, stronger shadows, re-check every pair.
- 60/30/10 is a default; a maximalist or monochrome direction can invert or abandon it.
- OKLCH lightness is perceptual, not WCAG luminance. Never assume a lightness value passes; compute it.

### 4.4 Motion *(personality is Tier B; safety is Tier A)*
Every animation explains a relationship, gives feedback, guides attention, or sets mood. Micro 120–250ms, transitions 300–500ms, ceremonial up to ~800ms. Animate `transform`, `opacity`, and with care `clip-path` and `filter`. Never layout properties on in-flow elements (the fixed nav in §9.1 is the one documented exception). Entrance = ease-out, exit = ease-in, unless the direction wants spring, linear, or stepped.

### 4.5 Layout and cognition
Gestalt (proximity, similarity, continuity, closure, figure-ground). Hick: fewer choices. Miller: chunk lists into groups of roughly 5–9, beyond ~7 add sub-groups or progressive disclosure. Reveal complexity on demand. Hierarchy check: primary action obvious, scannable in under 3 seconds, eye path intended.

### 4.6 Modern CSS toolkit (progressive enhancement, always with a working fallback)
`color-mix()` · `light-dark()` · container queries · `:has()` · `@property` for animated gradients · View Transitions · scroll-driven animations (`animation-timeline`, wrapped in `@supports`) · `clamp()` fluid type · `dvh` units · `font-optical-sizing` · `accent-color` · `color-scheme`. A feature that fails in an older browser must degrade to a usable, static layout.

### 4.7 Data visualization
Chart type follows the question: comparison → bar, trend → line, distribution → histogram, relationship → scatter. Direct-label instead of legends when possible. Honest axes and units. Never rely on hue alone to separate series (add shape, pattern, or labels). A chart can be art-directed; it cannot mislead.

## 5. Components and states

### 5.1 Component brief
For each component specify: purpose, sizes, variants, states, spacing, radius, type, interaction, accessibility behavior. Button hierarchy: primary (core goal), secondary, tertiary (low emphasis). Sizes sm 32 / md 40–44 / lg 48–56px height.

State table (Tier A):

| State | Behavior |
|---|---|
| Default | token defaults |
| Hover | subtle shift, only under `@media (hover: hover)` |
| Focus-visible | 2px `outline`, 2px offset, ≥ 3:1 against neighbors |
| Active | `scale(0.98)` + deeper color |
| Disabled | `opacity: .5`, `aria-disabled`, explain *why* nearby when not obvious |
| Loading | `aria-busy="true"`, visible label change ("Saving…"), spinner decorative |

### 5.2 Edge and error states (Tier A when data, input, or async is involved)
- **Empty**: first-use (explain + next action), zero-results (why + clear filters). Banned: a bare "Coming soon" with no path.
- **Errors**: recoverable ones are inline, specific, and say what to do ("Enter an email like name@site.com"), not "Error". Unrecoverable (offline, 500) look different and offer retry. More than 3 errors → add a summary at the top plus inline messages. Validate on blur first, live afterwards. Never discard input on failed submit.
- **Dependencies**: say why a field is disabled; re-validate dependents when upstream changes.
- **Long forms**: persist draft state; warn before leaving with unsaved changes.
- **Loading**: skeletons for known shapes, spinners for short unknown waits; anything over 2–3s needs progress or a skeleton.
- **Offline / stale**: tell the user the data may be old.
- **Destructive**: confirm, state the consequence, offer undo or cancel.
- **Overflow**: pick a strategy (ellipsis + title, show more, pagination) so content never clips silently.

## 6. Responsive and platform
Support 320 → 2560px+. Default breakpoints (bend if the content grid says so): 375 · 640 · 768 · 1024 · 1280 · 1536. Adapt hierarchy, nav, density, and interaction per breakpoint (touch targets, safe areas, hover vs tap, keyboard shortcuts on desktop, container queries for components).

### 6.1 i18n and RTL
Logical properties (`margin-inline-start`, `padding-block-end`, `inset-inline-end`) over physical. Mirror directional icons in RTL, never mirror neutral ones. Budget ~30–35% extra length for German/Finnish, plus taller line-height for Thai, Devanagari, CJK. If out of scope, state it.

## 7. Performance as UX
LCP (optimize critical image/font), CLS (reserve space, set image dimensions), INP (light handlers). SVG for icons, WebP/AVIF for photos, lazy-load below the fold. Max 3–4 font files, variable fonts, `font-display: swap`, size-adjusted fallbacks. Heavy effects (grain, blur, big shadows) are performance decisions; budget them.

## 8. UX writing
Text is interface: clear, short, action-oriented, in the direction's voice. Buttons say what happens ("Save changes"), not "Submit". Empty states and errors are the best place for personality.

## 9. Skeleton tokens (a runnable starting point, not an identity)

> Contrast pairs below are **computed**, not asserted (hue 250; table after the code). Change `--hue` first, then rerun §10; chroma at some hues clips out of gamut and shifts luminance. Shipping this unmodified on a full surface fails the Skeleton test (§2, Phase 7).

```css
:root {
  color-scheme: light dark;
  --hue: 250; /* identity knob: change it, then re-verify contrast */

  /* Spacing */
  --space-1: 4px;  --space-2: 8px;  --space-3: 12px; --space-4: 16px;
  --space-5: 20px; --space-6: 24px; --space-8: 32px; --space-10: 48px;
  --space-12: 64px; --space-14: 96px; --space-15: 128px; --space-16: 160px;
```

## 10. Contrast script (Tier A: run it, show inputs and ratio)

Tokens are OKLCH, so convert to sRGB before applying the WCAG formula. Save as `contrast.mjs`, edit `pairs`, run `node contrast.mjs`. Results within 0.2 of a threshold count as failing because browser gamut mapping differs slightly from clamping.

```js
const oklchToRgb = (L, C, hDeg) => {
  const h = (hDeg * Math.PI) / 180, a = C * Math.cos(h), b = C * Math.sin(h);
  const l = (L + 0.3963377774 * a + 0.2158037573 * b) ** 3;
  const m = (L - 0.1055613458 * a - 0.0638541728 * b) ** 3;
  const s = (L - 0.0894841775 * a - 1.291485548 * b) ** 3;
  const lin = [
    4.0767416621 * l - 3.3077115913 * m + 0.2309699292 * s,
    -1.2684380046 * l + 2.6097574011 * m - 0.3413193965 * s,
    -0.0041960863 * l - 0.7034186147 * m + 1.707614701 * s,
  ];
  return lin.map((v) => {
    v = Math.min(1, Math.max(0, v));
    return Math.round(255 * (v <= 0.0031308 ? 12.92 * v : 1.055 * v ** (1 / 2.4) - 0.055));
  });
};
const relL = (rgb) => {
  const [R, G, B] = rgb.map((v) => { v /= 255; return v <= 0.04045 ? v / 12.92 : ((v + 0.055) / 1.055) ** 2.4; });
  return 0.2126 * R + 0.7152 * G + 0.0722 * B;
};
const ratio = (a, b) => { const [x, y] = [relL(a), relL(b)].sort((p, q) => q - p); return (x + 0.05) / (y + 0.05); };

const H = 250; // keep in sync with --hue
// [label, foreground L/C/h, background L/C/h, minimum]
const pairs = [
  ["text-tertiary on bg-subtle (light)", [0.52, 0, 0], [0.965, 0.002, 0], 4.5],
  ["on-accent on accent (light)", [1, 0, 0], [0.55, 0.2, H], 4.5],
  ["accent-text on bg-subtle (light)", [0.5, 0.2, H], [0.965, 0.002, 0], 4.5],
  ["border-control on bg-surface (light)", [0.6, 0, 0], [1, 0, 0], 3],
  ["text-tertiary on bg-subtle (dark)", [0.68, 0, 0], [0.22, 0.005, 0], 4.5],
  ["on-accent on accent (dark)", [0.15, 0, 0], [0.72, 0.15, H], 4.5],
  ["border-control on bg-surface (dark)", [0.55, 0, 0], [0.19, 0, 0], 3],
];
for (const [name, fg, bg, min] of pairs) {
  const f = oklchToRgb(...fg), b = oklchToRgb(...bg), r = ratio(f, b);
  console.log(`${r >= min + 0.2 ? "PASS" : "FAIL"}  ${name}: (${f}) vs (${b}) → ${r.toFixed(2)}:1 (min ${min})`);
}
```
